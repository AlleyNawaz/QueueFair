# Decisions and dependency verification

## Scope and tradeoffs

- One Next.js application, PostgreSQL only. No cloud account, Redis, WebSockets or external messaging. Docker Compose is included; this implementation environment used local PostgreSQL 16 because Docker was unavailable.
- A service row is the serialization boundary. It is intentionally coarser than per-ticket row locking and provides a simple consistent lock order, including admin settings, rollover and old active work. The throughput limit is acceptable for this prototype.
- Custom credential flow uses maintained Argon2id and node:crypto, random opaque sessions, stored hashes, expiry, HttpOnly cookies and revocation. No custom password crypto or browser roles. Login limits are persistent per-account plus a conservative shared global bucket. Proxy/network identity handling requires deployment-specific trust configuration.
- Native controls and dialog provide small accessible forms. React Hook Form/shadcn are not necessary for the implemented forms. No chart library is needed for five aggregate analytics cards. Counter assignments are additive; removal and account provisioning UI remain future administration work.
- No destructive record deletion. Fixed Asia/Karachi timezone; no timezone edit and no overnight opening windows. Prefix is snapshotted per service day. No administrator transition override.
- Polling is deliberate. Hidden tabs pause; reconnect/focus refetch. Stale data remains visible with a warning. There is no offline issuance.
- Demo reset is an explicit guarded CLI command only. An unused ENABLE_DEMO_RESET example flag does not activate an HTTP reset handler. Synthetic seeded owners do not expose capabilities; self-service demos create fresh owned tickets.
- Urdu dictionaries and RTL cover key student/display labels; long explanations and staff/admin remain English. Push notifications, CSV and elaborate charts are omitted. No Kiro usage or recorded video is claimed.

## Installed versions and official sources

Registry resolution was checked, mutually compatible stable releases selected, and the lockfile retained. Prisma's registry latest was an 8.0 release candidate; stable **7.10.1** was chosen consistently for CLI, client and adapter. Initial ESLint 10 / TypeScript 7 peer mismatches were corrected to ESLint 9.39.2 / TypeScript 5.9.3 supported by the installed Next lint plugins; `pnpm peers check` reports no peer issues. ESLint 9 is an older compatibility dependency; reassess when those plugins support ESLint 10.
